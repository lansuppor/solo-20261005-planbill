# planbill

离线按量月结账单管理命令行工具。纯 Go 标准库实现，数据保存在本地目录的单个 JSON 文件中，原子写入、跨进程持久化，不依赖任何外部服务或数据库。

需要 Go 1.24 或更新版本。

## 快速开始

```sh
# 帮助（无参数、--help、-h 等价）
go run . --help

# 登记客户：customer add <标识> <名称> <单价分>
go run . customer add acme 月球咖啡馆 150

# 阶梯计费：登记方案并登记绑定方案的客户（固定单价客户不受影响）
go run . plan add std 标准阶梯 100:10 500:8 -:5
go run . plan show std
go run . customer add-plan beta 阶梯客户 std

# 含固定月费的阶梯方案：每月订阅费 1000 分 + 按量费
go run . plan add-fee sub 订阅阶梯 1000 100:10 -:5
go run . customer add-plan gamma 订阅客户 sub

# 方案变更：自 2026-11（UTC 自然月，含）起改用新方案，历史账单不重算
go run . plan add pro 续期阶梯 100:8 500:6 -:4
go run . plan change beta 2026-11 pro 续期采用新价格
go run . plan schedule beta          # 查询客户方案安排
go run . plan schedule beta 2026-11  # 查询该月有效方案

# 撤销误登记的方案变更：取消该价格安排并保留追溯，原变更永久保留、不可恢复
go run . plan revoke beta 2026-11 价格安排登记错误
go run . plan schedule beta          # 全部变更、原原因及撤销状态均可追溯

# 按月暂停：2026-11（含）至 2027-02（不含）暂停服务，暂停月不收用量、不出月费账单
go run . customer suspend beta 2026-11 2027-02 店面装修暂停营业
go run . customer suspensions beta           # 查询全部暂停区间
go run . customer suspensions beta 2026-12   # 查询该月是否暂停

# 按月提前恢复：客户无需等到原结束月，2026-12（含）起恢复服务，2026-11 仍暂停
go run . customer resume beta 2026-11 2026-12 装修完成提前复工
go run . customer suspensions beta 2026-12   # 该月实际未暂停（提前恢复释放）

# 按月订阅终止：自 2027-03（含）起永久结束后续服务，历史账务保留
go run . customer terminate beta 2027-03 停止合作
go run . customer termination beta          # 查询终止登记
go run . customer termination beta 2027-03  # 查询该月终止限制是否生效

# 导入用量（文件格式见下）
go run . usage import usage.csv

# 撤回一条误导入的未封账用量（原记录保留并标记原因，不可恢复）
go run . usage withdraw u-001 误导入记录
# 原子更正一条未封账用量：用全新记录替代错误的客户、时间或数量并保留来源
go run . usage correct u-002 u-002-fix beta 2026-09-16T10:00:00Z 12 客户与数量登记错误
go run . usage show u-002            # 按用量标识只读查询原始内容、撤回状态与前身/后继

# 月结并封账：bill settle <客户标识> <YYYY-MM>（按 UTC 自然月，左闭右开）
go run . bill settle acme 2026-09

# 按客户账期清单整批结算：一次确认多项配对，同时生成账单并封账
go run . bill settle-batch acme 2026-09 acme 2026-10 globex 2026-09

# 费用调整：正数补收、负数减免（只能作用于已存在账单，不开放已封账月份）
go run . bill adjust acme 2026-09 adj-001 500 漏算用量
go run . bill adjust acme 2026-09 adj-002 -100 客户补偿

# 撤销调整：只取消该笔金额影响，保留原记录与撤销原因
go run . bill revoke adj-001 录入错误

# 登记收款（正整数分，可分笔；只能作用于已存在账单）
go run . bill pay acme 2026-09 pay-001 500 银行转账
go run . bill pay acme 2026-09 pay-002 700 现金尾款

# 一笔汇款分配到同一客户的多个已结算月份（分配合计须等于总额）
go run . bill remit acme remit-001 900 季度汇款 2026-09:500 2026-10:400

# 自动分配汇款：只给客户、标识、总额与备注，按最早欠款账期依次偿还
go run . bill remit-auto acme remit-002 900 季度汇款

# 整批自动分配导入：一个文件含多个客户及同一客户多笔汇款（格式见下，- 为标准输入）
go run . bill remit-import remits.csv
go run . bill remit-import - < remits.csv

# 更正收款分配（修正入账月份，不重复收钱；合计仍等于原总额）
go run . bill correct remit-001 corr-001 入账月份登记错误 2026-09:300 2026-10:600

# 收款客户归属更正（把登记给错误客户的汇款整笔转给正确客户，不重复收钱）
go run . bill reassign remit-001 corr-002 正确客户 记错客户 2026-09:900

# 撤销收款：整笔撤销全部最新分配，永久保留原记录与撤销原因
go run . bill unpay pay-001 账号登记错误

# 部分退款：从已登记收款的最新分配中实际退回资金（可多次，直至退尽）
go run . bill refund remit-001 rf-001 多收退回 2026-09:100 2026-10:200

# 账后对账流水：按操作序号核对费用与收款变化，可回看指定序号后的余额
go run . bill ledger acme 2026-09
go run . bill ledger acme 2026-09 5

# 跨账期对账报表：一份报告核对多个账期在一段账后操作中的余额变化
go run . bill reconcile acme 2026-09 2026-10
go run . bill reconcile acme 2026-09 2026-10 0 5

# 查询账单（含调整净额、当前应付、实收、未收余额与全部历史）
go run . bill show acme 2026-09
```

## 数据目录

用 `--data-dir <目录>` 选择本地数据目录，缺省为当前工作目录下的 `./planbill-data`。
全部数据（客户、阶梯计费方案、方案变更、按月暂停区间与提前恢复记录、按月订阅终止登记、用量与撤回标记、用量更正关联、账单、封账状态、费用调整与撤销记录、收款与撤销记录、分配更正与收款客户归属更正记录）存于其中的 `state.json`：

- 每次命令都是一次独立的“读入—修改—整体落盘”，写入采用临时文件 + `rename` 原子替换；
- 账单与封账状态在同一次保存中持久化，只有完整保存成功后才报告成功；
- 已有数据损坏或不可读取时一律报错退出，**不会**被当作空库覆盖。

```sh
go run . --data-dir /var/lib/planbill customer add c1 一号客户 100
```

## 命令

| 命令 | 说明 |
| --- | --- |
| `customer add <标识> <名称> <单价分>` | 登记固定单价客户。单价为非负整数人民币分，创建后不可修改；重复标识、空标识、空名称均拒绝。 |
| `customer add-plan <标识> <名称> <方案标识>` | 登记绑定阶梯计费方案的客户。标识和名称规则同上；方案必须已存在；绑定创建后不可变更，已有客户不得换方案。 |
| `customer suspend <客户标识> <起月 YYYY-MM> <结束月 YYYY-MM> <原因>` | 为绑定阶梯方案的客户登记按月暂停区间。区间按 UTC 自然月解释为 `[起月, 结束月)`，包含起月、不包含结束月，与操作当天无关；结束月严格晚于起月。暂停月不接收用量，无论方案月费多少都不结算、不封账、不生成零金额账单；同一客户区间不得重叠（可相接，相接视为连续暂停）；起月须晚于该客户所有已封账月份，区间内已有用量时拒绝并指出冲突记录；固定单价客户不适用。记录由客户与起月共同标识、不可改写，相同结束月与原因的重放返回原记录且不写盘；不产生账后流水事件、不占用操作序号。 |
| `customer suspensions <客户标识> [YYYY-MM]` | 查询客户暂停区间（只读）：按原起月升序展示全部区间的原区间与原因、提前恢复信息和当前有效区间；给定月份时说明该月实际是否暂停；固定单价客户说明不适用暂停。查询成功或失败均不改写存档。 |
| `customer terminate <客户标识> <终止月 YYYY-MM> <原因>` | 为绑定阶梯方案的客户登记按月订阅终止：自终止月（UTC 自然月，含）起永久结束后续服务——不接收新用量、不结算、不封账、不收月费、不生成零金额账单；终止前月份仍按原规则补结算，历史账务全部保留。首次登记要求终止月晚于该客户全部已封账月份且终止月及之后没有有效（未撤回）用量；每客户只能登记一次，记录永久保留、不可修改或撤销；同月同原因重放返回原记录且不写盘，不同月份或原因拒绝；不产生账后流水事件、不占用操作序号。 |
| `customer termination <客户标识> [YYYY-MM]` | 查询客户按月订阅终止（只读）：展示保存的终止月与原因，或明确说明未登记；给定月份时说明终止限制是否生效；固定单价客户说明不适用终止。查询成功或失败均不改写存档。 |
| `customer resume <客户标识> <原起月 YYYY-MM> <恢复月 YYYY-MM> <原因>` | 为绑定阶梯方案的客户登记一项目标暂停的按月提前恢复：以客户与原起月共同识别目标暂停，月份按 UTC 自然月解释为 原起月（含）至原结束月（不含），与操作当天无关；目标暂停必须存在且须满足 `原起月 < 恢复月 < 原结束月`，原因非空，固定单价客户不适用。原暂停区间与原因永久保留，当前有效区间改为 `[原起月, 恢复月)`，恢复月起不再受该项暂停限制（可导入或接收更正用量并按当月有效方案结算、收取一次整月月费并从零累计阶梯，不补收仍暂停月份的月费）；已有账单、用量、方案安排和账后余额不变，其他月份已封账不妨碍登记，不占账后操作序号。每项暂停只能登记一次提前恢复，恢复记录永久保留、不可改写或撤销；以客户和原起月识别该项恢复，相同恢复月与原因重放返回保存信息和当前有效区间、不写盘，内容不同拒绝。原 `customer suspend` 仍按原结束月与原原因判重，相同重放不能延长有效暂停；后续封账、方案变更或新增暂停不阻止两类相同重放，也不撤销后来的暂停。释放月份允许另登记暂停，仍遵守封账限制，有效区间不得重叠但可相接；提前恢复只缩短目标区间，其他暂停独立生效。恢复记录整体原子保存后才报告成功；参数非法、目标缺失、冲突或保存失败均非零退出并说明原因，全部状态不变、不占用恢复登记，可原样重试。 |
| `plan add <标识> <名称> <上限:单价分>... <-:单价分>` | 登记按月累计用量的阶梯计费方案。至少一档；有限上限为严格递增的正整数，最后一档用 `-` 表示无上限；单价为非负整数分，可升可降；重复标识拒绝，创建后不可修改。 |
| `plan add-fee <标识> <名称> <月费分> <上限:单价分>... <-:单价分>` | 登记含固定月费的阶梯计费方案。阶梯规则同 `plan add`；月费为非负整数人民币分（`plan add` 省略月费视为 0），每账期按有效方案收取一次整月，不按天折算；月费与规则创建后不可修改。 |
| `plan show <标识>` | 查询阶梯计费方案的完整规则。 |
| `plan list` | 列出全部已登记的阶梯计费方案。 |
| `plan change <客户标识> <YYYY-MM> <方案标识> <原因>` | 为绑定阶梯方案的客户登记按月生效的方案变更。生效月（UTC 自然月，含）起改用目标方案，直到下一次变更，之前月份不受影响；只能按生效月递增追加（已撤销变更的月份仍占用，不可复用），且生效月须晚于该客户所有已封账月份；已有变更不可改写。 |
| `plan revoke <客户标识> <YYYY-MM> <原因>` | 撤销一项目标方案变更（取消误登记的价格安排并保留追溯）。以客户与目标变更生效月共同识别，仅限阶梯客户且目标必须存在，原因非空；原变更内容与原因永久保留，追加不可撤销的撤销记录，每项变更只能撤销一次，不占账后操作序号。有效方案只考虑未撤销变更，受影响区间、封账限制、逐条用量预检与幂等重放规则见“方案变更撤销”。 |
| `plan schedule <客户标识> [YYYY-MM]` | 查询客户方案安排（只读）：初始方案、按生效月排列的全部变更及原原因，以及每项变更的撤销状态与撤销原因；给定月份时展示该月实际有效方案（只考虑未撤销变更）。 |
| `usage import <文件>` | 整批导入用量。文件传 `-` 表示从标准输入读取。先校验再生效：任何一条有问题则整批失败，不留下新用量。 |
| `usage withdraw <用量标识> <原因>` | 撤回一条未封账用量（固定单价与阶梯客户均适用）：按原时间换算的 UTC 自然月已封账时拒绝，不改变账单或账后余额；原记录永久保留并标记撤回原因，不再参与结算与冲突检查，撤回不可恢复、标识不可复用；相同原因重放返回原记录且不写盘，换原因拒绝；不占用账后操作序号。 |
| `usage correct <原用量标识> <新用量标识> <新客户> <RFC3339 时间> <正整数数量> <原因>` | 原子更正一条未封账用量（固定单价与阶梯客户均适用）：用全新记录替代错误的客户、时间或数量并保留来源。原记录须存在且未撤回、其 UTC 月份未封账；新标识非空、不同于原标识且从未使用（同内容已有记录也不能充当替代）；新客户须存在，新时间的 UTC 月份未封账且未暂停，数量按新客户单价或当月有效阶梯方案做单条从零计价预检。成功后原记录按更正原因撤回、登记替代记录并永久保存关联（三项整体原子保存），原内容不可改写、更正不可撤销、不占账后操作序号；每条原用量只能更正一次，相同请求重放返回原更正及两条记录当前状态且不写盘，任一项不同拒绝。 |
| `usage show <用量标识>` | 按用量标识只读查询：原始客户、时间、数量、UTC 月份、是否撤回及撤回原因，以及该记录的直接前身、后继与对应更正原因（无关联时明确说明）；成功或失败均不改写存档。 |
| `bill settle <客户标识> <YYYY-MM>` | 按 UTC 自然月 `[月初, 下月初)` 归集用量，固定单价客户以“数量 × 固定单价”、阶梯客户按月累计分档计价生成一张账单并封账。重复结算返回原账单，不重新计费、不创建账单或调整。 |
| `bill settle-batch <客户标识> <YYYY-MM> [<客户标识> <YYYY-MM> ...]` | 按客户账期清单整批结算：一次确认多项客户与 UTC 自然月配对（至少一项，同一客户同一月份不得重复），同时生成账单并封账。整份清单先校验，任一项非法整批拒绝；已结算项返回原账单不重新计费；所有新账单与封账状态整体原子保存，不占用操作序号。 |
| `bill show <客户标识> <YYYY-MM>` | 展示账单：稳定账单标识、客户、月份、总数量、总金额、调整净额、当前应付、实收、未收余额，每条用量的标识、时间、数量和小计，以及按成功操作顺序排列的调整/撤销与收款/撤销历史。固定单价账单展示单价；阶梯账单展示计价类型、方案与完整规则、各档合计及每条用量的跨档分段。 |
| `bill adjust <客户标识> <YYYY-MM> <调整标识> <金额分> <原因>` | 对已存在账单追加费用调整。金额为非零有符号 64 位整数分：正数补收、负数减免；调整标识全局唯一非空，原因非空。 |
| `bill revoke <调整标识> <原因>` | 撤销一笔调整的金额影响。保留原记录与撤销原因，不改动其他调整、收款或原账单；原因非空。 |
| `bill pay <客户标识> <YYYY-MM> <收款标识> <金额分> <备注>` | 对已存在账单登记一笔实收。金额为正整数分，可分笔登记；等价于只含一项分配的汇款。收款标识全局唯一非空（与调整标识相互独立、可同名），备注非空。 |
| `bill remit <客户标识> <收款标识> <总金额分> <备注> <YYYY-MM:金额分>...` | 登记一笔汇款，按分配列表计入同一客户的多个已结算月份。总金额为正整数分；每项月份不得重复且须已有账单，金额为正整数分；分配合计须等于总额；每项不得超过对应未收余额，全部合法才整笔生效。 |
| `bill remit-auto <客户标识> <收款标识> <总金额分> <备注>` | 登记一笔自动分配汇款：只提供客户、收款标识、总金额与备注，由工具确定月份金额。只选择该客户当前已有账单，按 UTC 账期月升序依次偿还当前未收余额，跳过余额为 0 的月份，前一月份还清后才分配下一月，最后一月可部分偿还；不补结算、不跨客户、不留未分配款项；无欠款或总金额超过全部欠款时整笔拒绝。与 `bill pay`、`bill remit` 共用全局收款标识，按客户、总金额、备注判重；自动与显式分配登记间不得复用同一标识。 |

## 批量结算

- `bill settle-batch <客户标识> <YYYY-MM> [<客户标识> <YYYY-MM> ...]` 按客户账期清单整批结算：输入为非空的“客户标识 + YYYY-MM 月份”配对清单（参数个数须为偶数），可包含多个客户及同一客户的不同月份；同一客户同一月份不得在清单中重复出现。
- 整份清单**先确认可结算性**：每个客户必须存在、月份合法、未结算项在该 UTC 自然月有用量、计价不溢出；任一项非法都拒绝整批，并逐项指出清单位置、客户、月份及原因——不留下任何新账单，也不封闭任何原本未封账的月份。
- 各项独立采用该账期的计费规则：固定单价客户按数量乘单价；阶梯客户按账期月有效方案从零累计，不跨客户或月份共享累计量；用量按解析后的时间点、同一时间按标识排序，保留跨档明细与方案快照。数量、单价和金额使用有符号 64 位整数，全程整数计算并检查各账单的溢出；零费用账单正常封账。
- 已结算项返回原账单，不重新计费，允许清单混合已结算和未结算项；已有账单的标识、快照、金额、调整、收款、更正及撤销历史均不改变。账单仍以客户与月份确定身份，清单换序或重复提交不会重建账单；全部项目已结算时成功返回且**不改写存档**。批量结算不新增账后事件，也不占用全局操作序号。
- 所有新增账单与封账状态**整体原子保存**，完整保存成功后才报告成功：逐项列出客户、月份、稳定账单标识、原总金额及新增/已有状态，并报告两类条数；完整明细可由 `bill show` 和重复 `bill settle` 读回。保存失败整批不生效，不输出部分结算成功报告，原有账单、用量和其他状态不变，排除故障后原清单可重试。成功后的新月份遵守封账规则：拒绝新用量，相同用量重放仍跳过。

## 阶梯计费方案

- `plan add <标识> <名称> <上限:单价分>... <-:单价分>` 登记按月累计用量的阶梯计费方案：标识唯一非空、名称非空、至少一档有序阶梯；每档给出累计数量上限与每单位价格分，有限上限为严格递增的正整数，最后一档用 `-` 表示无上限；单价为非负整数分，可升可降；数量与单价均在有符号 64 位范围内。重复方案标识拒绝，方案创建后不可修改。`plan show` 查询完整规则，`plan list` 列出全部方案。
- `customer add-plan <标识> <名称> <方案标识>` 登记绑定已存在方案的新客户，标识和名称规则与 `customer add` 相同；绑定创建后不可变更，已有客户不得换方案。固定单价客户的登记与计费完全不变。
- 阶梯客户结算仍按 UTC 自然月归集，每个客户每月从零累计：用量按解析后的时间点升序、同一时间按标识字典序计价，各档仅对落入本档的数量收费——不把最高档价格套用全月，也不对每条用量重置阶梯；跨档记录分段计费，每条小计之和等于原总金额。
- 阶梯账单保存方案标识、名称与完整规则快照，展示计价类型、各档实际数量与金额，以及每条用量的跨档数量、单价和小计；不伪造统一单价。`bill show` 与重复 `bill settle` 返回相同计费明细。
- 阶梯客户导入时以单条数量从零计价校验金额，整批校验与去重规则不变；月累计数量、分档金额或总额溢出有符号 64 位范围时结算失败且不封账，全程整数计算。零费用账单正常封账。
- UTC 月界、封账重放、调整、收款、更正与账后流水对阶梯账单的行为与固定单价账单一致，同样满足 `0 ≤ 实收 ≤ 应付`。
- 旧存档中无方案的客户和账单按固定单价读取；重启后方案、绑定、账单及幂等全部保持。方案引用失效、账单明细或金额与计价规则不符的存档一律按损坏拒绝并保留原文件。

## 固定月费

- `plan add-fee <标识> <名称> <月费分> <上限:单价分>... <-:单价分>` 登记含固定月费的阶梯计费方案，支持“每月订阅费 + 按量费”的账单：月费为非负整数人民币分；`plan add` 省略月费视为 0。月费与阶梯规则创建后均不可修改，重复方案标识拒绝。`plan show`、`plan list` 与 `plan schedule` 均展示月费。
- 按**账期月的有效方案**收取一次整月月费，不按天折算，也不依赖操作当天；按月方案变更同时切换月费与阶梯规则，保留递增追加、封账限制与重放规则，历史账单不重算。
- **原总金额 = 月费 + 全月用量费**。用量仍按 UTC 自然月归集、按时间点及标识排序、从零累计分档计价；月费不计入总数量、各档金额或逐条用量小计，也不伪造用量记录。
- 月费大于 0 的方案即使无用量，单笔与批量结算也须生成账单并封账，展示总数量 0、空用量明细与用量费 0；月费为 0 的方案与固定单价客户仍在无用量时拒绝且不封账。
- 导入与方案变更的单条预检仍只检查用量费，月费不逐条累加；月费加全月用量费溢出有符号 64 位范围时结算拒绝且不封账。批量清单可混合含月费方案、旧方案与已有账单，任一项失败整批不生效。
- 账单永久保存实际月费与方案规则快照；`bill show` 与重复 `bill settle` 展示月费、用量费、原总金额及原有账后信息，重复结算不重复收费。调整、收款、更正、撤销与截止流水均以包含月费的原总金额为基础，仍满足 `0 ≤ 实收 ≤ 应付`；封账后拒绝新用量，相同用量重放仍跳过。
- 旧方案与旧账单缺少月费字段时按 0 读取，重启保持快照、余额与幂等。载入校验月费非负、账单月费快照符合账期方案、总金额等于月费加用量费，仅月费大于 0 的账单允许空用量明细；损坏或不可读文件一律拒绝并保留原文件。

## 方案变更

- `plan change <客户标识> <YYYY-MM> <方案标识> <原因>` 为**已绑定阶梯方案**的客户登记按月生效的方案变更，用于续期时采用新价格而不重算历史账单：自生效月（UTC 自然月，含）起改用目标方案（同时切换月费与阶梯规则），直到下一次变更；生效月之前的月份不受影响。固定单价客户不能登记变更；固定单价与方案规则本身仍不可修改。
- 创建客户时绑定的方案永久保留为**初始方案**；变更只追加、不改写：新变更的生效月必须**严格晚于**该客户已有变更的生效月（按生效月递增追加），且必须**晚于该客户所有已封账月份**。月份按 UTC 自然月解释，与操作当天无关。
- 一项变更由**客户与生效月**共同标识：相同目标方案和原因的重放返回原记录、不重复生效（即使后来追加了变更或相关月份已封账）；同一项内容不同（目标方案或原因不同）拒绝；其他客户可使用相同月份。变更不产生账后流水事件，也不占用全局操作序号。
- 登记前预检：对生效月起已导入的未封账用量，按目标方案**逐条从零计价**检查金额，任一条溢出有符号 64 位范围则整项拒绝并指出用量，不修改用量；月累计溢出仍由结算把关（拒绝且不封账）。
- 后续导入按**记录时间换算的 UTC 月份**的有效方案做单条金额预检，整批校验、去重与封账重放规则不变；结算按**账期月的有效方案**从零累计、按时间点与标识排序分段计费，数量和金额使用有符号 64 位整数并检查溢出。
- 新账单保存实际使用方案的名称、规则与分档明细快照；`bill show` 与重复 `bill settle` 保留原快照、金额与账后历史，调整、收款、更正与截止流水行为不变。
- `plan schedule <客户标识> [YYYY-MM]` 只读查询：展示初始方案、按生效月排列的变更及原因；给定月份时说明该月有效方案。
- 旧文件缺少变更记录时沿用原绑定；重启后安排、幂等与历史账单校验全部保持，账单方案必须符合账期安排。变更整体原子保存后才报告成功；引用缺失、月份非法、冲突、溢出或保存失败均非零退出并说明原因，业务状态不变，失败不占用客户月份，可重试。变更引用失效或内容损坏的存档一律按损坏拒绝并保留原文件。

## 方案变更撤销

- `plan revoke <客户标识> <目标变更生效月 YYYY-MM> <原因>` 取消误登记的价格安排并保留追溯：撤销接受客户、目标变更的生效月与非空原因，仅限绑定阶梯方案的客户，且目标变更必须存在；固定单价客户与不存在的月份槽位均拒绝。
- 原变更内容（目标方案、生效月与原原因）**永久保留**，撤销只追加一条**不可撤销**的撤销记录；每项变更只能撤销一次，撤销**不占用账后操作序号**，也不产生账后流水。用量内容、已有账单快照与账后余额一律保持不变，其他变更和暂停、提前恢复记录不改动。
- **有效方案只考虑未撤销变更**：撤销目标后，自其生效月（含）起沿用此前最后一项未撤销变更的方案，没有则用初始方案，直到其后下一项未撤销变更的生效月前；没有后一项则覆盖之后所有月份。该连续月份范围即本次撤销的**受影响区间**，按撤销当时的安排确定；连续撤销时每次都按当时安排重新确定区间，互不干扰。
- 首次撤销时，受影响区间内存在**已封账账单**则整项拒绝并指出月份；区间之外的已封账账单不妨碍登记。区间内的**有效（未撤回）用量**按撤销后各月有效方案**逐条从零预检用量费**：任一条溢出有符号 64 位范围则整项拒绝并指出用量记录；已撤回用量不参与预检。月累计数量及月费加用量费溢出仍由结算拒绝且不封账。
- 撤销以**客户与目标生效月**共同识别：相同原因的重放返回原撤销记录与当前安排、**不写盘**——即使后来相关月份封账、追加了新变更或撤销了其他项也成功，不改变既有状态；换原因拒绝，撤销记录不可改写、不可撤销。原 `plan change` 的相同重放须返回该变更的**已撤销状态**，不能恢复安排；对该月份提交不同内容的变更仍按不可改写拒绝。
- 新变更的生效月仍须**严格晚于该客户所有已登记变更的月份（包括已撤销项）**，且晚于所有已封账月份——撤销不释放月份槽位，原客户月份不能复用。
- 导入、用量更正以及单笔、批量结算统一按**跳过已撤销变更后的账期方案**计价：月费、阶梯从零累计、暂停规则、整批失败与原内容重放规则全部保持；已封账账单保存的方案快照不因撤销改变。
- `plan schedule <客户标识> [YYYY-MM]` 保留按生效月排列的**全部**变更（含已撤销项）、原原因及每项的撤销状态与撤销原因；指定月份时展示撤销后实际有效的方案。查询只读，成功或失败均不落盘。
- 撤销记录在同一次原子保存中整体落盘后才报告成功，展示客户、目标变更（原内容与原原因）、撤销原因与受影响区间；输入非法、目标缺失、冲突、预检或保存失败均非零退出并说明原因，全部状态不变、**不占用撤销登记**，可原样重试。
- 重启保持安排与幂等：旧存档无撤销信息时视为全部变更有效。载入时拒绝失效的撤销引用（目标变更不存在）、空撤销原因，或账单方案与撤销后有效安排不符的存档；损坏或不可读文件一律报错并保留原文件。

## 按月暂停

- `customer suspend <客户标识> <起月 YYYY-MM> <结束月 YYYY-MM> <原因>` 为**已绑定阶梯方案**的客户登记一段按月暂停区间，使暂停服务期间不接收用量、不产生月费账单。固定单价客户不适用暂停；原因非空。
- 月份均为 `YYYY-MM`，按 **UTC 自然月**解释为左闭右开区间 `[起月, 结束月)`：包含起月、不包含结束月，结束月必须严格晚于起月，与操作当天无关。不在任何暂停区间内的月份正常服务；不同客户的暂停互不影响。
- 同一客户的**当前有效区间不得重叠但可以相接**，相接视为连续暂停（提前恢复只缩短目标区间，故重叠判断按当前有效区间）；新登记的起月须**晚于该客户所有已封账月份**，暂停不改动初始绑定、方案变更或已有账单。
- 登记前检查新区间内**已导入的有效（未撤回）用量**：存在任一条即整项拒绝并指出冲突记录（标识与月份），不删除或改写用量；已撤回记录不参与冲突判断，可存在于随后暂停的月份；登记不检查方案安排，方案变更仍遵守原有限制并按生效月改变安排。
- 一项暂停由**客户与起月**共同标识，原区间与原因永久保留、记录不可改写：相同结束月与原因的重放返回原记录且**不写盘**（即使后来结算了恢复后的月份也须成功），不能借重放延长已被提前恢复缩短的有效暂停；结束月或原因不同则拒绝。暂停不产生账后流水事件，也不占用全局操作序号。
- 暂停月的新用量使**整批导入失败**并指出行号，合法项也不留下；库中已有用量的去重与封账重放规则保持。暂停月无论方案月费多少，单笔结算都拒绝且不封账、不生成零金额账单；`bill settle-batch` 的清单包含暂停月时整批拒绝，不留下任何新账单或封账，不输出部分成功报告。
- 恢复服务后按账期有效方案收取一次整月月费，用量从零累计分档计费，**不补收暂停月月费**。非暂停月份的无用量、金额溢出、重复结算及账后操作规则全部保持。
- `customer suspensions <客户标识> [YYYY-MM]` 为只读查询：按原起月升序展示全部暂停区间的原区间与原因、提前恢复信息和当前有效区间；给定月份时说明该月实际是否暂停及命中的当前有效区间（落在因提前恢复而释放的月份时明确说明已提前恢复）；固定单价客户说明不适用暂停。查询成功或失败均不改写存档。
- 登记在原子保存完成后才报告成功，展示客户、区间及原因；非法输入、引用缺失、区间冲突或保存失败均非零退出并说明原因，全部业务状态不变，失败不占用客户起月，可原样重试。
- 旧文件缺少暂停记录时视为正常服务；重启后区间、幂等与暂停限制全部保持。载入时拒绝客户引用失效、非法区间、同客户当前有效区间重叠，或当前有效暂停月内存在有效（未撤回）用量、账单的存档；不可读或损坏文件一律报错并保留原文件。

## 暂停提前恢复

- `customer resume <客户标识> <原起月 YYYY-MM> <恢复月 YYYY-MM> <原因>` 为已登记的按月暂停登记**按月提前恢复**，使客户无需等到原结束月即可重新使用服务；仅适用于绑定阶梯方案的客户，固定单价客户不适用，恢复原因非空。
- 以**客户与原起月**共同识别目标暂停；月份均为 `YYYY-MM`，按 **UTC 自然月**解释，与操作当天无关。目标暂停必须已由 `customer suspend` 登记，且严格满足 `原起月 < 恢复月 < 原结束月`（恢复月等于原起月或不早于原结束月均拒绝）。其他月份是否封账与本次登记无关——其他月份已封账不妨碍登记。
- 提前恢复**只缩短目标暂停的当前有效区间**：原暂停区间（`[原起月, 原结束月)`）与原原因永久保留，当前有效区间改为 `[原起月, 恢复月)`；自恢复月（含）起该项暂停不再限制服务。已有账单、用量、方案安排和账后余额一律不变；恢复不产生账后流水事件，也**不占用全局操作序号**。
- 每项暂停只能登记**一次**提前恢复，恢复记录永久保留、**不可改写或撤销**。以客户和原起月识别该项恢复：相同恢复月与原因的重放返回保存信息和当前有效区间、**不写盘**——即使后来恢复月已封账、发生方案变更或新增了暂停也成功，且不撤销后来的暂停；恢复月或原因不同则拒绝。
- 原 `customer suspend` 仍按**原结束月与原原因**判重：相同重放返回原记录、不写盘，不能借重放把已缩短的有效暂停延长回原结束月；结束月或原因不同仍拒绝。后续封账、方案变更或新增暂停都不阻止恢复登记与暂停登记这两类相同重放。
- 用量导入与更正、单笔和批量结算、新暂停登记及载入校验统一使用**当前有效区间**。释放的月份（恢复月至原结束月前）可按现有规则导入或接收更正用量并结算：采用**当月有效方案**、收取一次整月月费并**从零累计阶梯**，不补收仍暂停月份的月费；释放月无用量时按既有月费规则处理（月费大于 0 仍出仅月费账单），溢出、封账与整批失败规则保持不变。
- 释放月份允许**另登记暂停**：仍遵守既有封账限制（新暂停起月须晚于所有已封账月份），与各暂停的当前有效区间**不得重叠但可以相接**；提前恢复仅缩短目标区间，其他暂停独立生效。
- `customer suspensions` 按原起月展示每项暂停的**原区间与原因、提前恢复信息（恢复月与恢复原因）和当前有效区间**；给定月份时按当前有效区间说明该月实际是否暂停，落在提前恢复释放部分的月份会说明对应的提前恢复。查询成功失败均不写盘。
- 恢复记录在同一次原子保存中整体落盘后才报告成功；参数非法、目标暂停缺失、恢复月越界、内容冲突或保存失败均非零退出并说明原因，全部状态不变、**不占用**该项暂停的恢复登记，可原样重试。
- 重启后当前有效区间与两类判重全部保持；旧存档没有恢复记录时暂停**沿用原区间**。载入拒绝：恢复引用的目标暂停缺失、恢复月越界（不满足 `原起月 < 恢复月 < 原结束月`）、恢复原因为空、同客户当前有效区间重叠，或当前有效暂停月内存在未撤回用量、账单的存档；暂停原记录的其他校验保持不变，损坏或不可读文件报错并保留原文件。

## 按月订阅终止

- `customer terminate <客户标识> <终止月 YYYY-MM> <原因>` 为**已绑定阶梯方案**的客户登记按月订阅终止，永久结束后续服务并保留历史账务；仅限阶梯客户，固定单价客户不适用，原因非空。终止月按 **UTC 自然月**解释，与操作当天无关。
- 自终止月（含）起：**不接收新用量、不结算、不封账、不收月费、不生成零金额账单**。终止前月份仍按当月有效方案、暂停、月费及封账规则补结算；历史账单的调整、收款、更正、退款、撤销及对账继续可用——终止不减免费用、不退钱、不改变任何原记录或余额，也不占用账后操作序号。
- **每客户只能登记一次**，记录永久保留、不可修改或撤销，客户标识不能复用。以客户识别终止登记：**相同终止月与原因的重放返回原记录、不写盘**——即使后来补结算了较早月份或发生了账后操作也成功；**不同月份或原因拒绝**。
- 首次登记要求：终止月**晚于该客户全部已封账月份**，且终止月及之后**没有有效（未撤回）用量**；冲突则整项拒绝并指出月份或用量标识，不删除或改写任何记录。**已撤回记录不阻塞**，可在暂停期间终止；方案变更、暂停及提前恢复记录全部保留，相关操作仍按原规则处理，但**不能越过终止边界恢复服务**。
- 终止限制只约束**新用量及更正替代记录的目标客户和目标 UTC 月份**：导入混入终止月及之后的新用量时整批拒绝并指出行号；已有用量的相同导入和已有更正的相同重放继续成功、不恢复记录；终止前未封账用量可按原规则更正到其他客户；更正被拒绝时原记录、替代标识及关联均不变。单笔结算拒绝终止月及之后的月份；批量清单包含这类月份时整批不新增账单或封账、不报告部分成功。
- `customer termination <客户标识> [YYYY-MM]` 为只读查询：展示保存的终止月与原因，或明确说明未登记；给定月份时说明终止限制是否生效；固定单价客户说明不适用终止。查询成功或失败均不改写存档。
- 登记整体原子保存后才报告成功并展示客户、终止月和原因；输入非法、客户缺失、冲突或保存失败均非零退出并说明原因，全部状态不变，不占终止登记，可原样重试。
- 重启保持状态和判重；旧存档缺少终止信息视为未终止。载入时拒绝客户引用失效、非阶梯客户、非法终止月、空原因，或终止月及之后存在有效用量、账单的存档；已撤回用量和保留的安排正常读取。损坏或不可读文件一律报错并保留原文件。

## 用量撤回

- `usage withdraw <用量标识> <原因>` 撤回一条误导入的用量，固定单价与阶梯客户均适用；原因非空。首次撤回须找到原记录，且按原时间换算的 UTC 自然月**尚未封账**；已封账用量拒绝撤回，不改变账单或账后余额。
- 成功后原客户、时间、数量与标识**永久保留**，仅追加撤回状态与原因：撤回**不可恢复**、标识**不可复用**。撤回只作用于该条记录，不改动账单与账后余额，不产生账后流水事件，也**不占用全局操作序号**。
- 同一用量**相同原因**的重复撤回返回原记录且**不写盘**——即使后来该月已封账或暂停仍成功；**换原因拒绝**。目标缺失、原因非法、封账限制或保存失败均非零退出并说明原因，全部状态不变、不留下撤回标记，可原样重试。
- 只有**未撤回**用量参与单笔及批量结算、方案变更预检和暂停区间冲突检查：阶梯结算将剩余记录按原有时间点及标识顺序**从零累计重新分档**；撤回最后一条后按无用量规则处理——正月费非暂停月仍可出仅月费账单，零月费或固定单价拒绝且不封账。撤回记录可存在于随后暂停或已封账的月份，不参与费用或用量冲突判断；方案变更与暂停仍遵守各自封账限制。
- 导入仍按**客户、解析后的时间点和数量**与原内容判重：已撤回记录的相同重放计入重复跳过、**不能恢复**，内容不同使整批失败；暂停、封账及当前方案下金额预检只约束**全新用量**，不得阻止原内容重放（相同重放也不受后续方案计价溢出影响）；文件内重复与失败整批不生效规则保持。
- `usage show <用量标识>` 为只读查询：展示原始客户、时间、数量、UTC 月份、是否撤回及撤回原因；成功或失败均不改写存档。
- 旧存档缺少撤回信息视为全部用量有效，跨进程保持状态及重放规则。载入拒绝撤回目标失效、撤回原因为空、账单引用已撤回用量或未完整包含该客户当月有效用量的存档；仍检查留存原记录的格式、正数量和客户存在性，不把已撤回记录视为待计费用量；不可读或损坏存档拒绝并保留原文件。

## 用量更正

- `usage correct <原用量标识> <新用量标识> <新客户> <RFC3339 时间> <正整数数量> <原因>` 对一条未封账用量做**原子更正**：不是改写原记录，而是登记一条全新替代记录替换错误的客户、时间或数量，并永久保留来源。固定单价与阶梯客户均适用；新数量为正整数（有符号 64 位），原因非空，时间须为 RFC3339（按解析后的瞬间比较）。
- 首次更正要求**原记录存在且未撤回**，且按原时间换算的 UTC 自然月**未封账**；新标识非空、**不同于原标识且从未使用**——即使库中已有一条客户、时间、数量完全相同的记录，也不能让它充当替代记录；**新客户须存在**，新时间对应的 UTC 月份**未封账且未暂停**。
- 计价预检：固定单价客户按 **新数量 × 新客户固定单价**、阶梯客户按**新时间 UTC 月份的有效方案**对新数量做**单条从零计价**，全程整数计算并检查溢出；阶梯的**月累计溢出仍由结算把关**（更正只保证单条可计价）。
- 成功时一次性完成三项并**整体原子保存**后才报告成功：原记录按更正原因标记**撤回**、登记**替代记录**、永久保存**更正关联**。原内容不可改写，更正**不可撤销**，更正**不占用账后操作序号**，不改变任何已有账单及账后余额。输出展示双方内容、各自 UTC 月份、当前状态与更正原因。
- 任何失败都非零退出并说明原因，**全部业务状态不变**：失败的新增不留下撤回标记、替代记录或关联，不占用新标识，可原样重试。
- 每条原用量**只能更正一次**，以原标识识别该项更正。相同的新标识、客户、解析后的时间点、数量与原因**重放**时返回原更正及两条记录当前状态、**不写盘**；任一项不同（含时间只是字符串不同但瞬间相同以外的任何差异）拒绝。
- **替代记录是一条普通的新用量**：可以继续被更正（形成前身→后继链），也可以按原规则 `usage withdraw` 撤回；导入两端原内容仍按原规则判重跳过，**不恢复**已撤回记录。后来发生封账、暂停、方案变化，或替代记录已被撤回/继续更正，都**不能阻止**对原更正的相同重放，也不能恢复任何记录。
- 更正后只有**有效（未撤回）用量**参与单笔及批量结算、方案变更预检和暂停冲突检查；阶梯月按有效记录的原时间点及标识顺序**从零重新累计分档**，月费与无用量规则保持不变（撤回最后一条有效记录后，正月费非暂停月仍可出仅月费账单）。
- `usage show <用量标识>` 在原有信息之外展示该记录的**直接前身、后继及对应更正原因**，无任何更正关联时明确说明“无”；查询成功或失败均只读、不落盘。
- 重启保持更正关联、撤回状态与幂等；旧存档缺少更正信息视为无更正。载入校验拒绝：关联引用的原记录或替代记录缺失、原记录未撤回或撤回原因与更正原因不符、同一替代记录有多个来源、更正关联成环，以及替代记录内容与保存的新内容不一致的存档。替代记录后来被**合法撤回或继续更正**不会被误判为损坏。损坏或不可读存档一律报错并**保留原文件**。

## 费用调整与撤销

- 调整只能作用于**已存在账单**（已结算月份），不会开放已封账月份；账单的标识、总数量、单价、用量明细与原总金额永远不变。
- **当前应付 = 原总金额 + 全部未撤销调整金额**，必须介于 0 与有符号 64 位最大值之间，全程整数运算；越界的调整或撤销会被拒绝，业务状态不变。
- 调整标识全局唯一：按**客户、月份、金额、原因**判断重复——内容完全相同的重放返回已保存记录，不再次增减应付；任何一项不同（含跨客户、跨月份复用）均拒绝。首次新增失败不占用该标识。
- 撤销只取消该笔调整的金额影响，原记录与撤销原因永久保留。相同标识与相同原因的重复撤销幂等成功、不新增记录；改用其他原因拒绝。
- 撤销后重放原调整仍返回其**已撤销**状态，不会重新生效。
- 若撤销会使当前应付越界，则拒绝且该调整保持有效；可在其他合法调整改变余额后重试。
- `bill show` 与重复 `bill settle` 会展示调整净额、当前应付，以及按成功操作顺序排列的调整/撤销历史（含调整标识、金额、原因、当前状态与撤销关联），便于核对费用变化。

## 收款登记与撤销

- 收款只能登记到**已存在账单**（已结算月份）；账单与调整记录永远不因收款而改动。
- 一笔收款 = 同一客户的一笔汇款（总额）+ 分配列表（月份：金额）。`bill pay` 登记单账单收款，视为只有一项分配的汇款；`bill remit` 把一笔汇款分配到同一客户的多个已结算月份，两个入口共用同一个全局收款标识。
- **当前应付 = 原总金额 + 全部未撤销调整净额**；**实收 = 当前归属本客户的全部未撤销收款按最新分配在该月计入并扣除退款后的合计**（收款可能经 `bill reassign` 在客户间整笔转移，归属按更正时间线取当前值）；**未收余额 = 当前应付 − 实收**。三者全程整数计算，始终满足 `0 ≤ 实收 ≤ 当前应付 ≤ 有符号 64 位最大值`。
- 收款总额与每项分配必须是**正整数分**，支持分笔收款；分配合计必须等于总额（合计溢出拒绝）；首次登记时每项分配不得超过对应月份的未收余额（应付 − 实收），任何一项不合法则整笔不生效；当前应付为 0 的账单不能登记正额收款。
- 收款标识在所有客户与月份间全局唯一；收款与调整标识**相互独立、允许同名**，各自判重与撤销。相同收款标识按**客户、总额、备注及月份-金额对应关系**判重（分配顺序不影响身份）：内容完全相同的重放返回原记录，不再次计入实收，也不受当前余额变化影响；任何一项不同（含跨客户、跨月份、跨分配组合复用）均拒绝。首次新增失败不占用该标识。
- 撤销收款整笔生效：取消该笔在全部分配月份上的最新实收（经更正的以最新分配为准），不接受部分撤销；原记录、分配、更正、备注与撤销原因永久保留，应付、其他收款与调整均不改变。相同收款标识与相同原因的重复撤销幂等成功、不新增历史；改用其他原因、撤销不存在的目标均拒绝。
- 撤销后重放原收款仍返回其**已撤销**状态，不会恢复实收。
- 新增费用调整或撤销调整若会使当前应付低于实收（按最新分配计入），一律拒绝并保持原状态；可先撤销误登记的收款，再重试符合约束的调整。
- `bill show` 与重复 `bill settle` 在原字段与调整历史之外，补充实收、未收余额，以及按成功操作顺序排列的收款/更正/撤销历史（含收款标识、总额、本账单分配、备注、状态、更正前后分配、撤销关联与原因）；所有曾涉及该账单的月份（即使后来被更正移出）都保留完整历史；重复结算不产生收款。
- 旧的 `state.json` 缺少收款、更正或退款记录时视为零实收、零更正、零退款；旧版单账单收款格式（`month` + `amount_fen`）载入时自动归一化为一项分配。重启后余额、操作顺序、幂等与撤销约束全部保持。

## 自动分配收款

- `bill remit-auto <客户标识> <收款标识> <总金额分> <备注>` 登记一笔自动分配汇款：调用方只提供客户、收款标识、总金额与备注，月份金额由工具确定。总金额为正整数人民币分（有符号 64 位整数），标识与备注非空。
- 首次登记只选择该客户**当前已有账单**，按 UTC 账期月升序依次偿还**当前未收余额**（调整、最新收款分配、撤销及退款后的净额）：跳过余额为 0 的月份，前一月份还清后才分配下一月，最后一月可部分偿还。**不补结算、不跨客户、不留未分配款项**；无欠款或总金额超过全部欠款时整笔拒绝。各月余额与分配全程整数计算，多个账单欠款合计超过 64 位上限也不会误拒合法金额。
- 成功保存为**一笔普通收款及首次自动分配**，占用一个账后全局序号，不按月份拆成多笔；该收款可沿用分配更正、整笔撤销、部分退款及退款后固定分配的规则，原账单、应付与其他收款不变，各月仍满足 `0 ≤ 实收 ≤ 应付 ≤ 有符号 64 位最大值`。结果展示收款标识、总额、首次分配、最新分配、当前状态及这两份分配所涉月份的当前余额；`bill show`、重复结算、`bill ledger` 与 `bill reconcile` 都能追溯这笔收款，跨月登记只作为一次操作。
- 自动入口与 `bill pay`、`bill remit` 共用全局收款标识；自动登记按**客户、总金额、备注**判重：相同请求返回原收款及当前状态，不写盘、不重新分配、不增加序号；以后新增账单、调整、更正、退款或撤销均不改变该规则，不恢复旧分配或已退、已撤销金额；内容不同拒绝。**同一标识在自动与显式分配登记间复用拒绝**；`pay` 与 `remit` 之间的原有判重保持；收款标识仍与调整、更正、退款标识相互独立。
- 自动登记身份与首次分配永久保留，重启后判重与余额保持；旧收款及旧版单月格式按显式分配登记读取。记录、分配与序号整体原子保存后才报告成功；输入非法、客户缺失、标识冲突、欠款不足或保存失败均非零退出并说明原因，所有业务状态不变，不占标识或序号，可原样重试。

## 收款整批自动分配导入

- `bill remit-import <文件>` 从 CSV 文件整批导入自动分配汇款，文件传 `-` 表示从标准输入读取。批内可有多个客户及同一客户的多笔汇款；每行只给出客户、全局收款标识、总金额（正整数人民币分，有符号 64 位整数）与非空备注，文件至少一条记录。
- 整份文件**先校验再生效**：客户须存在；按输入顺序逐行处理，全新收款基于**原存档及本批前面已接受的新收款**形成的余额，按 UTC 账期月升序偿还已有账单欠款——跳过零余额月份，前月还清才分配下一月，末月可部分偿还。欠款按调整、最新收款分配、撤销及退款后的净额计算；**不补结算、不跨客户、不留未分配款项**，无欠款或金额超出该客户欠款则该行非法并整批拒绝。全程整数计算，跨账单欠款合计超过 64 位上限也不会误拒合法汇款。
- 导入与 `bill remit-auto` **共用收款标识和自动登记身份**，按客户、总额、备注判重：存档已有或本批先前出现的相同记录计为重复跳过，不重新分配、不占序号；内容不同（客户、总额或备注任一不同）整批拒绝；显式登记（`bill pay`、`bill remit`）的收款标识不能复用。后来新增账单、更正、退款或撤销不阻止相同重放，不恢复款项或旧分配；文件名不参与判重。
- 每笔新增保存为**一笔普通自动收款**：首次分配永久保留，按首次出现顺序各占一个**连续递增的账后全局序号**，重复行不占序号，**不按月份拆笔**；后续更正、退款和整笔撤销遵守现有规则。`bill show`、`bill ledger`、`bill reconcile` 能按逐笔序号追溯，历史截止不提前计入后续记录，各月仍满足 `0 ≤ 实收 ≤ 应付 ≤ 有符号 64 位最大值`。
- 整批新增记录、分配与序号**一次原子保存**完成后才报告成功；按输入顺序列出各行新增或跳过、收款标识、首次与最新分配，并汇总新增笔数与重复行数。**全为重复时不写盘**。解析、校验或保存失败均非零退出并说明原因，行问题指出行号；全部业务状态不变，不占任何新标识或序号，不输出部分成功，可排除故障后重试。
- 重启后分配、余额与判重保持；旧存档及旧单月收款可直接读取。损坏或不可读存档一律拒绝并保留原文件。

## 收款分配更正

- `bill correct <收款标识> <更正标识> <原因> <YYYY-MM:金额分>...` 把一笔**未撤销**收款的当前分配整笔替换为完整新分配，用于修正入账月份；总额不变，因此不重复收钱。客户、总额、备注、原账单及应付均不改变。
- 新分配列表非空：每项月份为 `YYYY-MM`、不得重复且须是**当前归属客户已结算账单**（收款经 `bill reassign` 转给其他客户后，本命令只调整新归属客户的月份），各项金额为正整数分，合计必须等于原收款总额；全程有符号 64 位整数运算并检查溢出。
- 以**当前最新分配**为起点：撤去该笔当前分配再计入新分配后，涉及月份均须满足 `0 ≤ 实收 ≤ 应付`（其他收款不变），全部合法才整笔生效；任一月份越界则整笔拒绝，状态不变。可连续更正，每次以当时最新分配为起点。
- 更正标识全局唯一非空，与收款、调整标识**相互独立、可同名**，但与收款客户归属更正（`bill reassign`）**共用同一命名空间、不可跨类型复用**；按**目标收款、原因及新月份-金额对应关系**判重（列表顺序无关）：内容完全相同的重放返回原更正记录，不改分配、不增历史，后续更正、归属更正、退款或收款撤销不影响此规则；任何一项不同均拒绝。首次新增失败不占用该标识或序号。
- 首次登记的收款内容（含原始分配）永久保留，`bill pay` / `bill remit` 仍据此判重：相同重放返回当前状态，不恢复旧分配；内容不同拒绝。
- 更正结果展示关联收款、更正标识、原因、完整前后分配及涉及月份的当前余额。
- `bill ledger` 把每次更正在前后分配涉及的账单上作为**共用全局序号的单个事件**展示：本月前后分配、实收差额与事后余额；回放按当时分配进行，截止序号之后的更正及撤销不提前影响余额，最新余额与 `bill show` 一致。

## 收款客户归属更正

- `bill reassign <收款标识> <更正标识> <目标客户> <原因> <YYYY-MM:金额分>...` 纠正登记给错误客户的一笔汇款，把整笔实收转给正确客户，**不重复收钱**：成功后整笔撤去当前归属客户最新分配的全部实收，计入目标客户新分配的实收，总额不变。
- 首次登记仅限**未撤销且未退款**收款；更正标识非空，与 `bill correct` **共用且不可跨类型复用**（与收款、调整、退款标识仍相互独立、可同名）；目标客户须存在并**异于当前归属客户**，固定单价与阶梯客户均适用。
- 新分配非空：`YYYY-MM` 月份不重复且须是**目标客户已有账单**，各项为有符号 64 位正整数人民币分，合计必须等于原总额；全程整数计算、检查溢出。
- 涉及账单（转出侧当前分配各月与转入侧新分配各月）在更正后都必须满足 `0 ≤ 实收 ≤ 应付 ≤ 有符号 64 位最大值`：转出侧实收不得为负（未退款收款撤去整笔当前分配必然非负），转入侧计入后不得超过目标账单当前应付；其他收款、账单与应付不变，**不补结算**。任一项非法、冲突、超额或溢出都整笔拒绝，全部状态不变，不占标识或序号，可重试。
- 一次更正只占**一个账后全局序号**（转出与转入共用同一序号）；更正记录永久保留、**不可撤销**，可连续更正（再次归属更正，或之后做同客户分配更正）。**原登记客户、总额、备注、首次分配及自动或显式登记身份都不改写**：`payment` 仍挂在首次登记客户名下，判重始终按首次登记身份。
- 按更正标识核对**目标收款、目标客户、原因及月份-金额关系**（顺序无关）：相同重放返回原更正与当前状态，**不写盘、不增序号**；后续更正、退款或撤销不影响重放，不恢复旧归属或款项；任一项不同（含跨收款、跨类型复用）拒绝。原收款各入口（`bill pay` / `bill remit` / `bill remit-auto` / `bill remit-import`）仍按首次登记身份判重。
- 更正后 `bill correct` 只调整**当前客户**的月份；`bill refund`、`bill unpay` 作用于**当前归属及最新分配**；**首次退款后禁止新增两类更正及整笔撤销**，已有请求（收款、两类更正、退款）的相同重放仍成功。费用调整与新收款按迁移后的余额约束（转出释放的欠款可再收款，转入占满后目标账单不得再收）。
- 结果展示前后客户、完整前后分配、原因及涉及月份在两侧的余额。`bill show` 与重复结算保留曾涉及账单的完整历史（转出侧保留转出事件与零金额撤销事件，转入侧保留转入事件）；`bill ledger`、`bill reconcile` 在转出与转入两侧以**同一序号**列实际转出或转入金额，各自只计本客户范围内金额，按当时归属回放——截止序号之后的迁移不提前影响较早余额，终点为最新时与 `bill show` 一致；查询只读。
- 记录、归属与序号整体原子保存后才报告成功；重启后归属、历史与判重全部保持，兼容旧存档与旧版单月收款（旧文件无归属更正即视为收款始终归属于首次登记客户）。载入时拒绝引用缺失、非法分配、序号冲突、非法操作先后（如首次退款后又出现归属更正）与逐步余额越界（含转入实收超过目标账单应付）的存档，损坏或不可读文件原样保留。

## 部分退款

- `bill refund <收款标识> <退款标识> <原因> <YYYY-MM:金额分>...` 从一笔**未撤销**收款的最新分配中实际退回资金：只减少对应月实收、增加未收余额，不改变应付、其他收款或费用调整；原收款总额、备注、原始分配和账单永久保留。
- 月份金额清单至少一项：月份为 `YYYY-MM`、不得重复，金额为正整数分；仅允许退**最新分配**涉及的月份，各月金额不超过该笔在该月分配减该月累计退款（只动本收款余额，不借用其他收款）。允许多次部分退款及退尽余额；任一项非法则整笔拒绝，状态不变、不占退款标识或序号，可原样重试。
- 退款记录永久保留且**不可撤销**；**首次退款后该收款的最新分配固定**，拒绝新增分配更正、收款客户归属更正及整笔撤销（无退款的收款仍按原规则处理）；已有收款、两类更正的相同重放仍成功，不恢复已退金额或旧分配。退款只作用于退款时的**当前归属客户**。
- 退款标识全局唯一非空，与收款、调整、更正标识**相互独立、可同名**；按**目标收款、原因及月份-金额对应关系**判重（清单顺序无关）：内容完全相同的重放返回原记录且不写盘——即使后来已退尽；任何一项不同均拒绝。每笔退款占用一个递增的账后全局序号。
- 费用调整及其撤销、新收款均按**退款后余额**约束（例如退款释放的未收余额可再登记收款）；成功结果显示退款标识、关联收款、原因、各月退款及剩余可退额。
- `bill show` 与重复 `bill settle` 保留原信息并展示退款历史和当前余额；`bill ledger` 把每笔退款在其发生序号作为减少实收的单个事件展示，截止序号之后的退款不影响历史余额；`bill reconcile` 把跨月退款作为**一次操作**列出范围内逐月变化及汇总，不按整笔总额重复累减，最新余额与账单一致。
- 旧 `state.json` 缺少退款记录时视为无退款，旧版单账单收款仍可直接退款。载入时核验退款引用、逐月累计不超退、操作先后合法（退款后不得更正或整笔撤销）与余额不变量，异常一律按数据损坏拒绝，保留原文件。

## 账后对账流水

- `bill ledger <客户标识> <YYYY-MM> [截止操作序号]` 是**只读**查询：成功或失败都不改写存档、不占用序号、不新增记录。
- 以目标账单**原总金额为初始应付、零实收**为起点，只回看账后变化；把该账单的调整、调整撤销、收款、分配更正、收款客户归属更正（转出或转入）、收款撤销与退款合并为一条按**全局操作序号**（调整/收款/两类更正/退款及其撤销共用的已保存序号）升序的流水。
- 调整改变应付，收款、更正、归属更正与退款只改变实收；撤销在其发生序号抵消对应原操作——已撤销记录在撤销之前仍计入，不按当前撤销状态删除原事件。多月汇款只以本账单分配改变实收；分配更正在其发生序号把本账单分配由前值替换为后值（前后分配涉及的账单都会出现该事件）；**归属更正在同一序号把实收整笔转出原客户（本账单为负增量）或转入目标客户（正增量），转出与转入两侧共用同一序号**；整笔撤销在同一序号取消撤销时最新归属客户的最新分配；退款在其发生序号减少当时归属客户的本账单实收且不可撤销；同名调整、收款、更正与退款按类型分别关联。
- 截止序号省略表示最新，`0` 只返回初始余额，截止包含该序号；负数、非整数或超过存档全局序号上限拒绝；因其他客户或月份操作造成的序号空档合法。**按当时归属回放：截止序号之后的归属更正不提前影响较早余额。**
- 输出账单标识、客户、月份、原总金额、存档全局序号上限、查询采用的截止序号，以及截止以内每个事件的序号、类型、原记录标识、金额影响、原因或备注、撤销关联和事件后的应付/实收/未收余额（收款事件同时说明汇款总额与本账单分配，更正事件同时说明关联收款与本账单前后分配，归属更正事件说明转出/转入对方客户与本账单转出或转入金额）；末尾给出截止时的三项余额，无事件时明确空流水。最新余额与 `bill show` 一致，截止之后的更正、归属更正与撤销不影响历史余额也不混入流水。
- 查询前核验目标账单的**完整流水**：每个事件之后都必须满足 `0 ≤ 实收 ≤ 应付 ≤ 有符号 64 位最大值`（不只检查最终余额），即使异常发生在截止序号之后也拒绝；引用失效、序号重复或撤销先于原操作同样拒绝，不输出部分正常的报告。累计补收或收款发生额超过 64 位上限但每步余额合法时仍正常输出。
- 旧文件缺少调整、收款、更正或退款记录时按空历史处理；旧版单账单收款按一项分配读取。

## 跨账期对账报表

- `bill reconcile <客户标识> <起月 YYYY-MM> <止月 YYYY-MM> [起始操作序号 截止操作序号]` 用一份**只读**报表核对一个客户在多个账期上的余额变化：成功或失败都不改写存档、不占用序号、不新增记录，同一存档的重复查询结果稳定。
- 账期范围包含首尾（起月不得晚于止月，月份必须合法）；只选择该客户范围内**当前已存在**的账单，不补结算、不按操作时间筛选账单。范围内无账单时成功输出空报表及零汇总。
- 起止操作序号可选且须成对给出：省略表示 `0` 至存档最新序号；给定须满足 `0 ≤ 起点 ≤ 终点 ≤ 存档全局序号上限`，因其他客户或月份操作造成的序号空档合法。所有选中账单在序号 0 以原总金额为应付、零实收起算；起止余额分别取对应序号操作完成后的状态，变动区间为起点之后、终点以内（含终点）。
- 报表按月份展示账单标识、原总金额及两端的应付、实收、未收余额，并给出各列汇总；**逐月两端余额与相同截止的 `bill ledger` 一致，终点为最新时与 `bill show` 一致**。
- 区间内的调整、调整撤销、收款、分配更正、收款客户归属更正（转出或转入）、收款撤销与退款按全局操作序号合并展示，每次操作只出现一次：说明序号、类型、记录标识、原因或备注、撤销或更正关联，列出范围内各月的应付及实收变化和事件后的汇总余额；同名的调整、收款、更正与退款标识按类型区分，互不混淆。归属更正在转出客户一侧列负增量、在转入客户一侧列正增量，两侧共用同一序号，各自只计本客户范围内金额。
- 调整仅纳入所属账期在范围内的操作；收款按登记时归属与分配、收款撤销按撤销时最新归属的最新分配、分配更正按前后分配、归属更正按转出/转入两侧、退款按当时归属客户各月退款额判断是否涉及范围。多月汇款只按范围内分配计入实收，不重复累加汇款总额；跨月退款作为一次操作只按范围内各月退款额减少实收，不重复累减整笔总额；范围内转移即使汇总变化为 0 也保留，跨范围转入或转出按实际差额计入；**终点之后的归属更正不提前影响结果**。
- 金额全程整数计算并以人民币分准确展示：单账单仍满足 `0 ≤ 实收 ≤ 应付 ≤ 有符号 64 位最大值`，多账单汇总按 128 位整数精确累加，合计超过有符号 64 位上限仍准确输出。
- 输出前核验所有选中账单的**完整流水**（与 `bill ledger` 相同的逐步核验），即使异常发生在终点序号之后也拒绝，不输出部分报表。客户缺失、参数非法、文件不可读或数据损坏均非零退出并说明原因，保留原文件。旧存档与旧版单账单收款格式直接可用。

## 用量文件格式

CSV（UTF-8），首行为固定表头，之后每行一条记录，字段恰好四个：

```csv
usage_id,customer_id,time,quantity
u-001,acme,2026-09-15T10:00:00Z,3
u-002,acme,2026-09-16T18:00:00+08:00,2
```

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `usage_id` | 全局唯一用量标识 | 非空，跨所有客户全局唯一 |
| `customer_id` | 客户标识 | 必须是已登记客户 |
| `time` | 用量时间 | RFC3339，如 `2026-09-15T10:00:00Z`、`2026-09-16T18:00:00+08:00`；归集月份时先换算到 UTC |
| `quantity` | 数量 | 正整数，有符号 64 位整数范围内 |

整批导入的判定规则：

- 先完整校验（客户存在性、格式、唯一性，以及对**全新用量**的约束：金额可行性——固定单价客户检查数量×单价、阶梯客户按记录时间换算 UTC 月份的有效方案以单条数量从零计价——是否落入暂停区间、已封账月份或不早于终止月），全部通过后才生效；
- 已存在的用量标识，按**客户、解析后的时间点、数量**比较（`Z` 与 `+00:00` 等表示同一瞬间的写法视为相同）：内容相同算重复并跳过——即使该月后来已封账、暂停或后续方案计价会溢出也不受阻；已撤回记录的相同重放同样计入重复跳过，不会恢复记录；内容不同则拒绝整批；
- 文件内部的重复记录遵循同样规则；
- 结果报告新增条数与重复跳过条数；失败时逐条指出问题记录的行号与原因。

## 收款文件格式

`bill remit-import` 使用 CSV（UTF-8），首行为固定表头，之后每行一笔汇款，字段恰好四个：

```csv
payment_id,customer_id,total_fen,note
pay-001,acme,900,季度汇款
pay-002,globex,500,"货款, 含九月尾款"
```

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `payment_id` | 全局收款标识 | 非空；与 `bill remit-auto` 共用，自动与显式分配登记（`bill pay`、`bill remit`）之间不得复用 |
| `customer_id` | 客户标识 | 必须是已登记客户 |
| `total_fen` | 总金额 | 正整数人民币分，有符号 64 位整数范围内 |
| `note` | 备注 | 非空；可含逗号，按 CSV 规则加引号 |

整批导入的判定规则：

- 至少一条记录；先完整校验（表头与字段格式、客户存在性、标识归属、欠款可分配性），全部通过后才一次原子生效；
- 按输入顺序处理：全新收款基于原存档及本批前面已接受的新收款形成的余额自动分配，同一客户的多笔汇款依次偿还，前一笔还清的月份不再分配给后一笔；
- 存档已有或本批先前出现的相同收款标识，按**客户、总金额、备注**比较：内容完全相同算重复并跳过（不重新分配、不占序号，即使后来新增账单、更正、退款或撤销也不受阻）；内容不同、复用显式分配标识或客户不存在均拒绝整批；
- 无欠款或总金额超出该客户当前全部欠款的行非法，整批拒绝、不留任何新收款；
- 结果按输入顺序逐行列出新增或重复跳过、收款标识、首次与最新分配，并报告新增笔数与重复行数；全为重复时不写盘；失败时逐条指出问题行的行号与原因。

## 整数与金额

数量、单价、金额均为有符号 64 位整数；金额单位为人民币分（如 `150` 分即 `1.50 元`）。
全部运算使用整数完成并做溢出检查，不经过浮点数。任何乘法或加法溢出都会使对应导入或结算失败，业务状态保持不变。

## 退出码

- `0`：成功；
- `2`：命令行用法错误（未知命令、参数数量不对、月份格式之外的调用问题），原因写入标准错误；
- `1`：业务错误（客户不存在、整批导入失败、无用量、月份无效、调整/收款标识冲突、金额越界、收款超额、数据损坏等），原因写入标准错误。

每次操作的记录与余额状态在同一次原子保存中整体落盘，完整成功后才报告成功；格式非法、引用不存在、标识冲突、金额越界或保存失败均非零退出且业务状态不变，失败的新增不占用标识。
